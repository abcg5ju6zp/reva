# 编辑会话代际移动交接 - 产品需求文档

## Overview
- **Summary**: 当协作用户正在应用中以读写方式编辑文档时，若另一端移动或重命名该文件，系统须以资源身份为键建立新的"编辑代际（generation）"，在切换目录项之前冻结新的编辑打开请求，并由活动会话、应用提供者、存储锁、下载/上传入口共同确认新引用；旧令牌只允许完成已开始且代际匹配的保存，不得在新位置提交后覆盖内容。
- **Purpose**: 消除移动过程中锁、打开令牌、保存回调与新路径分离所导致的保存失败、旧位置内容被迟到保存覆盖，以及同一份文档出现两个可编辑入口的问题；保证移动在应用回调超时、锁刷新失败、崩溃中断三类失败下均可恢复且语义确定。
- **Target Users**: 通过 Web/桌面端在应用（WOPI 类编辑器及参考实现 demo 应用）中协作编辑文档的终端用户；配置与运维 Reva 网关的管理员。

## Goals
- 移动带活动读写编辑会话的资源时，以资源身份为单位建立新代际，所有编辑活动在移动后统一指向新引用，只存在一个可编辑入口。
- 在目录项切换前冻结新的编辑打开请求，并排空已开始的同代际保存。
- 活动会话、应用提供者、存储锁、下载/上传入口对新引用的确认全部可追踪、可持久化、可重放。
- 应用回调超时、锁刷新失败、目录项已移动而会话接管未完成三类失败具有确定的恢复语义，恢复过程复用既有代际和会话，不产生重复移动或替代会话。
- 移动确认后旧路径不再签发编辑令牌；迟到解锁与应用回调受代际约束；最后一个会话关闭后才清理旧引用。
- 无活动编辑会话的移动、只读打开、普通下载、不支持锁的存储，完全保持既有行为。

## Non-Goals
- 不改变 CS3 对外协议（不修改/新增 go-cs3apis 的 protobuf 接口）；代际状态、会话标识、保存状态通过既有 `Opaque`、既有 HTTP 回调端点与内部端口传递。
- 不实现跨存储提供方（cross-provider）移动；仅覆盖同一存储提供方内的移动/重命名（沿用网关现有的同提供方约束）。
- 不在本仓库内实现外部 wopiserver（独立 Python 项目）的真实接管逻辑；仓库内提供内部接管端口、demo 应用提供者参考实现与 HTTP 回调端点，wopiserver 的适配作为后续工作。
- 不改变只读/预览打开、普通一次性下载的既有语义与权限判定。
- 不引入对共享锁（`LOCK_TYPE_SHARED`）的新支持；本协议以独占写锁为前提。

## Background & Context
- Reva 的网关是高层协调点：`Move`、`OpenInApp`、`SetLock/GetLock/RefreshLock/Unlock`、`InitiateFileDownload/Upload` 均经网关；网关还用 `TransferSharedSecret` 为数据网关签发传输 JWT（现有 claims：`target`、`version_key`）。
- 存储 FS 接口（`pkg/storage/storage.go`）已定义 Move 与四类锁操作：EOS 驱动支持锁（锁挂在 inode 上），本地驱动（localfs）对锁返回 `NotSupported`。
- 应用提供者链路：HTTP appprovider 服务（`/app/new`、`/app/open`、`/app/notify`）→ 网关 `OpenInApp` → gRPC appprovider 服务 → 驱动（wopi/demo）。仓库当前不存在编辑会话注册表或代际概念。
- 已确认决策：状态持久化采用 SQL 存储库；应用交接采用"内部端口 + demo 参考实现"；测试做到单元 + 重启恢复（离线可运行）。

## Functional Requirements

### 会话与代际
- **FR-1**: 系统以资源身份（`ResourceId`：storage id + space id + opaque id）为键管理编辑会话与代际；同存储提供方内移动不改变资源身份，每次移动为该身份建立一个新代际（G0 → G1…），代际序号严格递增。
- **FR-2**: 一次成功的读写模式（`VIEW_MODE_READ_WRITE`）`OpenInApp` 产生一个编辑会话并登记；会话绑定当前代际，记录用户、应用提供者、锁标识与已签发的下载/上传入口标识。只读/预览打开不登记编辑会话。
- **FR-3**: 代际状态机至少包含：`active`（当前服务代际）、`freezing`（已冻结新编辑打开、正在排空在途保存）、`moving`（目录项切换中/已切换、会话接管中）、`confirmed`（各方已确认新引用、新代际开始服务）、`cleanup`（旧引用清理）。每次状态迁移与各方确认结果必须持久化。
- **FR-4**: 会话关闭由应用关闭回调与/或解锁事件驱动；旧代际的引用与状态仅在绑定该代际的最后一个会话关闭后才允许清理。

### 移动协议
- **FR-5**: 网关收到 Move 时，先解析源引用并判定：存储是否支持锁、该资源身份是否存在活动读写编辑会话。仅当"支持锁且存在 ≥1 个活动读写会话"时启用代际移动协议；否则完全走既有 Move 路径。
- **FR-6**: 协议第一步为该资源身份创建新代际并进入 `freezing`，在切换目录项之前冻结新的编辑打开请求：针对该身份的新读写打开被拒绝为可重试状态（或被冻结到切换完成后重定向到新引用），不得签发旧代际编辑令牌；只读/预览打开不冻结，继续既有流程。
- **FR-7**: `freezing` 期间允许"已开始且代际匹配"的在途保存完成（保存会话在 `InitiateFileUpload` 时登记并绑定代际）；目录项切换须等待在途保存排空或由应用回调确认其内容已在新引用捕获后方可进行。
- **FR-8**: 切换目录项（存储 Move）前后，新代际记录阶段 `moving`；随后逐项完成并持久化各方确认：活动会话接管、应用提供者确认新引用、存储锁在新引用确认（旧位置锁在新锁确认前不释放）、下载/上传入口按新路径重新签发。全部确认后代际进入 `confirmed`。
- **FR-9**: 新代际 `confirmed` 后：新编辑令牌只对新代际签发；旧路径不再签发任何编辑令牌；新的保存只能提交到新引用。

### 旧令牌与迟到事件
- **FR-10**: 目录项在新位置提交（新代际 `confirmed`）后到达的旧代际保存，即使其令牌形式有效、即使它在冻结前已登记为在途，也必须拒绝——不得在新位置提交后覆盖内容；拒绝须可由调用方区分于普通网络失败。
- **FR-11**: 迟到解锁受代际约束：携带旧代际/旧锁标识的解锁不得释放新代际位置上的锁；只有当前代际的锁持有者可解锁。
- **FR-12**: 迟到应用回调（保存/关闭）受代际与幂等约束：同一（会话标识, 资源身份, 代际, 回调序号）的重复回调只生效一次；旧代际保存回调在提交后拒绝；关闭回调用于会话关闭计数与最终清理判定。

### 三类失败的恢复
- **FR-13（应用回调超时）**: 等待应用提供者保存/接管确认超时后，不得假定成功或失败；须按（会话标识, 资源身份）核对保存是否已落账：已保存则继续协议，未保存则继续等待或在可安全回退时恢复旧位置服务；核对与重发须幂等，不产生重复保存、重复会话。
- **FR-14（锁刷新失败）**: 接管过程中锁在新引用的刷新/再确认失败时，保留原位置并恢复服务：旧位置锁始终有效，已切换的目录项回移（或通过重启恢复回移），新代际废弃，旧代际解除冻结；不得在锁状态不确定时提交新代际。
- **FR-15（目录项已移动而接管未完成）**: 崩溃发生在目录项切换之后、各方确认完成之前时，重启须从持久化存储中恢复该代际所处阶段并继续驱动，直到 `confirmed` 或安全回退；恢复复用同一代际和同一会话集合。
- **FR-16（禁止掩盖）**: 三类失败的恢复均不得通过发起第二次移动、新建代际或新建会话来掩盖问题；在同一资源身份上重复到达的 Move 请求须识别到进行中的代际并加入/恢复它，而不是创建并行移动。

### 既有行为豁免
- **FR-17**: 没有活动读写编辑会话的移动，直接执行既有 Move，不创建代际、不冻结、不持久化额外状态。
- **FR-18**: 只读/预览打开在移动各阶段均可继续，按既有权限与视图降级逻辑处理；普通一次性下载不做代际门禁，沿用既有签发与传输流程。
- **FR-19**: 存储对锁返回 `NotSupported` 时，移动、打开、下载、上传全部沿用既有行为，不产生任何代际状态。

## Non-Functional Requirements
- **NFR-1（可恢复性）**: 代际、会话、各方确认、在途保存登记均在状态迁移点同步写入 SQL；进程在任意阶段崩溃后，仅依赖持久化状态即可恢复到正确阶段，不依赖内存。
- **NFR-2（幂等性）**: 移动、接管、保存回调、解锁、清理全部操作对重复投递安全；重复请求的结果与单次一致。
- **NFR-3（可配置性）**: 功能可经网关配置启用/关闭，并可配置 SQL DSN、应用回调超时、在途保存排空等待上限、锁刷新相关参数；默认关闭或在无活动会话时零行为变化。
- **NFR-4（可测试性）**: 协调核心通过端口接口与具体存储/应用解耦，支持以 fake 存储与 fake 应用提供者进行完整离线测试，包含重启恢复重放。
- **NFR-5（可观测性）**: 代际状态迁移、各方确认、三类失败的检测与恢复决策均有结构化日志，可按资源身份和会话标识关联。
- **NFR-6（兼容性）**: 不修改对外 CS3 协议；未启用该功能的部署行为与此前完全一致；现有单元测试保持通过。

## Constraints
- **Technical**: Go + Reva v3；沿用 `cfg.Decode` 配置、rgrpc/rhttp 注册、SQL 管理器（`database/sql` + 既有驱动）等既有模式；传输 JWT 扩展 claims 须与数据网关现有验签兼容（旧数据网关忽略新增 claims）。
- **Business**: 外部 wopiserver 的接管不在本次交付范围；本次以内部端口 + demo 参考实现承载协议并保证可测试。
- **Dependencies**: SQL 数据库（复用部署中已有 DB 配置方式）；网关现有的存储注册、应用注册与数据网关地址解析能力。

## Assumptions
- 同存储提供方内移动/重命名保持资源身份（opaque id/inode）不变；若某存储驱动移动后 inode 变化，该驱动上的协议行为不在本次保证范围内。
- 编辑会话以成功的读写 `OpenInApp` 为起点，以应用关闭回调与解锁的关联事件为关闭信号；参考实现（demo）中这些信号由仓库内组件产生，WOPI 部署中未来由适配 wopiserver 的端口产生。
- 编辑期间写锁由/为应用持有，锁标识可与编辑会话关联；不存在"无锁的活动读写编辑会话"。
- 所有外部移动请求（WebDAV MOVE、gRPC Move）均经网关；直连存储提供方的内部旁路不在覆盖范围。

## Acceptance Criteria

### AC-1: 活动会话移动产生单一新代际与单一编辑入口
- **Type**: `rule`
- **Given**: 资源 R 在存储 S 上有 ≥1 个活动读写编辑会话，S 支持锁
- **When**: 对 R 发起同提供方内移动到新路径
- **Then**: 为 R 的资源身份创建序号递增的新代际；移动确认后所有会话、锁与编辑入口指向新引用；不存在仍可编辑的旧入口
- **Pass Condition**: 状态存储中新代际为 `confirmed`；旧路径读写打开被拒绝为不可编辑；新路径读写打开成功；旧代际无在服编辑入口
- **Evidence**: 协调器状态记录 + 移动前后打开操作的表测试断言

### AC-2: 目录项切换前冻结新编辑打开且只读不受影响
- **Type**: `rule`
- **Given**: R 的新代际处于 `freezing`
- **When**: 分别发起新的读写打开与只读/预览打开
- **Then**: 读写打开被冻结/拒绝为可重试，不签发旧代际编辑令牌；只读/预览打开按既有流程成功
- **Pass Condition**: 读写打开返回可重试冻结状态且无新会话登记；只读打开成功、权限判定不变
- **Evidence**: 冻结阶段的打开表测试

### AC-3: 在途同代际保存可排空完成
- **Type**: `rule`
- **Given**: 冻结前已登记、绑定旧代际的保存正在进行
- **When**: 排空阶段等待该保存
- **Then**: 保存可在目录项切换前完成并被记录；目录项切换不在其完成前发生
- **Pass Condition**: 在途保存成功落账；切换事件发生在所有已登记保存完成或被应用确认捕获之后
- **Evidence**: 排空时序测试（完成顺序断言）

### AC-4: 提交后旧代际保存被拒绝
- **Type**: `rule`
- **Given**: 新代际已 `confirmed`（目录项已在新位置提交）
- **When**: 一个旧代际保存到达（含冻结前已登记的在途保存）
- **Then**: 保存被拒绝，不写入新引用、不覆盖任何内容
- **Pass Condition**: 拒绝错误可与网络失败区分；存储内容（新引用）字节/版本不变
- **Evidence**: 提交后迟到保存的拒绝测试与内容校验

### AC-5: 各方确认齐备才进入 confirmed
- **Type**: `rule`
- **Given**: 代际处于 `moving`
- **When**: 活动会话接管、应用提供者、存储锁、下载/上传入口逐项确认
- **Then**: 任一方未确认前代际不得 `confirmed`；全部确认后才 `confirmed` 并只在新代际签发编辑令牌
- **Pass Condition**: 缺任一确认时状态保持 `moving`；齐备后转 `confirmed`；旧位置锁在新锁确认前不被释放
- **Evidence**: 确认项组合表测试（逐项缺失与齐备）

### AC-6: 应用回调超时按会话与资源身份核对
- **Type**: `rule`
- **Given**: 等待应用提供者保存/接管确认超时
- **When**: 按（会话标识, 资源身份）发起幂等核对
- **Then**: 已保存/已接管则继续协议；未保存则继续等待或安全回退；不产生重复保存或重复会话
- **Given(补充)**: 同一确认重复到达
- **Then(补充)**: 只生效一次
- **Pass Condition**: 两种核对结果分支行为正确；重复确认后保存次数/会话数不增加
- **Evidence**: 超时核对分支测试 + 幂等重复测试

### AC-7: 锁刷新失败保留原位置并恢复服务
- **Type**: `rule`
- **Given**: 接管中新引用锁刷新/再确认失败
- **When**: 执行恢复
- **Then**: 已切换目录项回移、旧代际解除冻结恢复服务、旧位置锁仍有效；新代际废弃；锁状态不确定时不提交
- **Pass Condition**: 旧路径可继续打开并保存；锁仍由原持有者持有；无 `confirmed` 新代际残留
- **Evidence**: 锁刷新失败回退测试

### AC-8: 目录项已移动而接管未完成时重启恢复阶段
- **Type**: `rule`
- **Given**: 崩溃点位于目录项切换之后、各方确认完成之前，状态已持久化
- **When**: 进程重启并执行恢复
- **Then**: 从持久化阶段继续驱动同一代际和同一会话集，直至 `confirmed` 或安全回退；不新建代际、不新建会话
- **Pass Condition**: 恢复后代际/会话标识与崩溃前一致；最终状态确定；恢复过程零新增代际和会话
- **Evidence**: 对每一中断阶段注入崩溃并用全新协调器 + 同一 SQL 存储重放的测试

### AC-9: 重复移动加入进行中的代际
- **Type**: `rule`
- **Given**: R 的代际移动正在进行（任意未确认阶段）
- **When**: 同一资源身份上再次收到 Move
- **Then**: 识别并加入既有代际的恢复/等待，不创建第二个代际或并行移动
- **Pass Condition**: 该资源身份始终只有一个进行中代际；两次请求最终收敛到同一结果
- **Evidence**: 重复移动收敛测试

### AC-10: 迟到解锁受代际约束
- **Type**: `rule`
- **Given**: 新代际已 `confirmed`，锁位于新引用
- **When**: 携带旧代际/旧锁标识的解锁到达
- **Then**: 解锁被拒绝或忽略，新位置锁保持；当前代际持有者的解锁可成功
- **Pass Condition**: 旧代际解锁后锁仍存在；当前代际解锁成功
- **Evidence**: 迟到解锁表测试

### AC-11: 最后一个会话关闭后才清理旧引用
- **Type**: `rule`
- **Given**: 旧代际仍有 N（≥1）个未关闭会话
- **When**: 逐个关闭会话
- **Then**: 前 N-1 个关闭后旧引用/状态保留；第 N 个关闭后执行清理
- **Pass Condition**: 清理恰好发生在最后一个会话关闭时；此前旧代际状态可查
- **Evidence**: 会话关闭计数与清理时序测试

### AC-12: 豁免路径完全保持既有行为
- **Type**: `rule`
- **Given**: 以下四种情形之一：无活动会话的移动；只读/预览打开；普通一次性下载；存储对锁返回 NotSupported
- **When**: 执行对应操作
- **Then**: 请求结果、权限判定、令牌签发与既有实现一致，不创建任何代际/会话状态
- **Pass Condition**: 四类操作结果与未启用功能时一致；状态存储中无相关记录
- **Evidence**: 四类豁免情形的对照测试

### AC-13: 代际状态机与协调核心的工程质量
- **Type**: `rubric`
- **Dimension**: 状态机表达清晰度、端口边界、失败分支覆盖与日志可关联性
- **Scale**: 1-5
